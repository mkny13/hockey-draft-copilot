## Findings

### a. Credentials and `.env` — OK

- `git ls-files | grep -iE '(^|/)\.env|\.pem$|\.key$|secret|credential'` returns nothing.
- `git grep -iE '(api[_-]?key|token|secret|password|BEGIN .*PRIVATE)'` (lockfiles excluded)
  matches only the AGENTS.md sentence stating that no credentials are used.
- No `.env` loader (no `dotenv` dependency). `process.env` reads are configuration only:
  `server.js:8-11` (`PORT`, `HOST`, `DRAFT_STATE_FILE`, `WS_PING_MS`),
  `scripts/run_tests.js:143-147` (`TEST_TIMEOUT_MS`, `TEST_SLOW_MS`),
  `scripts/ingest_espn_adp.js:7` (`HASHTAG_HTML`), `mcp/lib/fetch.js:11` (`NHL_MCP_CACHE_DIR`).
- No database or pooled connection URLs exist. `.gitignore` covers the private board
  (`draft_data.local.json`), live state (`draft_state.json`) and `mcp/.cache/`.

### b. Process execution — OK, one follow-up

- `grep -rn child_process --exclude-dir=node_modules`: `scripts/run_tests.js:3`,
  `test/test_server.js:7`, `test/test_live_data_guard.js:9`. Every call is
  `spawn(process.execPath, [<fixed file>], …)` (`run_tests.js:51`, `test_server.js:64,981`,
  `test_live_data_guard.js:24`): no shell, no user-controlled arguments.
- `mcp/` has no process execution.
- `.claude/hooks/block_live_data.py` parses stdin JSON, reads only `tool_input.file_path`,
  compares its basename to a fixed set, and never executes or opens the path. It fails open
  (exit 0) on internal errors by design, so a hook bug never wedges a session.
- **Follow-up:** the hook matcher in `.claude/settings.json` is `Edit|Write|MultiEdit|NotebookEdit`,
  so a `Bash` tool call (`echo > draft_state.json`, `rm draft_data.local.json`) is not guarded.
  *Recommended fix:* add a `Bash` matcher whose check blocks commands that name a protected file
  as a write/remove target.

### c. Server origin boundary — Fixed here, one follow-up

- **Fixed here:** `ALLOWED_ORIGIN` (`server.js:191`) used to accept any `https://*.espn.com` or
  `https://*.yahoo.com` origin, so any ESPN/Yahoo page (e.g. an XSS on a news subdomain) could
  read `/draft_data.json` (the private `draft_data.local.json` board) via CORS and POST picks or
  `/api/reset`. It now accepts only `https://fantasy.espn.com`, `https://*.fantasysports.yahoo.com`
  and `http(s)://localhost|127.0.0.1` on any port — the same hosts as the extension's
  `host_permissions`. `test/test_server.js` proves `https://www.espn.com`,
  `https://sports.yahoo.com` and `https://fantasy.espn.com.evil.io` get 403 on `POST /api/reset`
  and no `Access-Control-Allow-Origin` on `GET /api/state`, and that a WebSocket handshake from
  `https://www.espn.com` is rejected; the existing allowed-origin assertions still pass.
- One regex drives every check: the CORS middleware (`server.js:194-216`, headers only for
  allowed origins, 403 for foreign non-GET and for foreign/missing-origin `OPTIONS`), WS
  `verifyClient` (`server.js:374`) and the connection handler's second check (`ws.close(1008)`).
- `/api/repair-pick` (`server.js:639`) and `/api/evaluation` (`server.js:505`) are registered
  after that middleware, so they sit behind it like every other route.
- **Follow-up:** the server does not check the `Host` header. A DNS-rebinding page (attacker
  hostname re-resolved to `127.0.0.1`) is same-origin with the server, so the browser sends no
  `Origin` on its GETs and could read `/draft_data.json`; with `HOST=0.0.0.0` a LAN peer can
  also read it. *Recommended fix:* reject requests whose `Host` is not `localhost` /
  `127.0.0.1` (any port) unless `HOST` was explicitly widened.

### d. Server input bounds — OK

- Body limit: `express.json({ limit: '64kb' })` and `express.urlencoded(… '64kb')`
  (`server.js:174-175`); oversize/malformed bodies get a 4xx from the error handler
  (`server.js:178`).
- `/api/pick` (`server.js:516`): name via `validatePickName` (1–80 chars, no control chars,
  `server.js:66`), `round`/`pickInRound` via `parseBoundedInt(…, 1, 1000)` (`server.js:101`),
  history capped at 2000 entries.
- `/api/repair-pick` (`server.js:639`): `pickNumber` via `parseBoundedInt(…, 1, 2000)`, same
  name validation and 2000-entry cap, must be below `currentPick`, must not repeat a recorded
  pick number or player. It takes only `pickNumber` and `name` from the body; team/position
  come from the board, so it accepts less client input than `/api/pick`.

### e. Extension — OK

- `yahoo-sync/manifest.json`: `permissions: ["storage"]` only; `host_permissions` and
  content-script `matches` are `https://fantasy.espn.com/*`, `https://*.fantasysports.yahoo.com/*`
  (plus `http://localhost:3333/*` in `host_permissions` for the health check). No bare
  ESPN/Yahoo domains, no `tabs`, `scripting` or `<all_urls>`.
- `chrome.storage.local` holds `syncUrl` and `status` (health snapshot) only. The #114 retry
  queue (`pendingQueue`, `yahoo-sync/content.js:20`) is in memory, not in storage.
- `syncUrl` is validated before use by `validateSyncUrl` in both `background.js:5` and
  `content.js:8` (must parse as `http:`/`https:`, else falls back to `http://localhost:3333`),
  and in `popup.js:75` before saving. Stored URLs and player names are escaped at render time
  (first pass, #19).

### f. Bookmarklet — OK

- `public/js/bookmarklet.js` targets fixed URLs `http://localhost:3333/api/pick` and
  `/api/reset` (lines 2-3). It sends `{ name, isMine, round, pickInRound }` (line 73) and a
  bodyless reset only after a `confirm()` (lines 26-33). Its requests carry the draft page's
  origin, which stays allowed on the fantasy hosts; on any other ESPN/Yahoo page they are now
  refused, which is intended.

### g. MCP server — OK, one follow-up

- Outbound hosts are a fixed list of constants in `mcp/lib/sources.js:5-7`
  (`moneypuck.com`, `api.nhle.com`, `api-web.nhle.com`); tool arguments never supply a scheme
  or host, so they cannot steer requests to another host.
- Numeric path parts are validated: `season` is an integer 1917–2100 (`sources.js:20-24`),
  `playerId` must match `/^\d+$/` or comes from the player index (`tools.js:348`), `date` must
  match `YYYY-MM-DD` (`tools.js:415`).
- Cache: `NHL_MCP_CACHE_DIR` or `mcp/.cache/` (gitignored). File names are the SHA-1 of the
  URL (`fetch.js:22-24`), so arguments cannot choose a cache path. Writes are best-effort.
- Transport is stdio (no listening socket).
- **Follow-up:** the `schedule` tool's `team` argument is only upper-cased
  (`names.js:24-28`) before being interpolated into the
  `club-schedule-season/<team>/…` path (`sources.js:82-83`), so a value like `../x` can reach
  a different path on `api-web.nhle.com` (host unchanged). *Recommended fix:* reject `team`
  values that do not match `/^[A-Z]{2,3}$/` after alias normalisation.

### h. Dependencies — Fixed here, one follow-up

- **Fixed here:** `.github/dependabot.yml` scanned npm at `/` and GitHub Actions only; it now
  also has an `npm` entry for `/mcp` (weekly, `non-major` group). `test/test_docs.js` fails if
  any directory holding a `package.json` (outside `node_modules`) lacks a Dependabot npm entry.
- `cd mcp && npm audit`: `found 0 vulnerabilities` (2026-10-20).
- **Follow-up:** root `npm audit` (2026-10-20) now reports 1 high: `source-map-js` 1.2.1
  (GHSA-68fv-2mgg-jv7q, event-loop DoS on crafted source maps), reached only through the dev
  dependency `jsdom` → `css-tree`. It is test-time only and never parses untrusted source maps.
  *Recommended fix:* take the Dependabot security update or run `npm audit fix` to bump the
  lockfile.
- `npm audit` stays out of CI by decision: transient advisories would block unrelated merges,
  and Dependabot covers it.

  `npm test`. No secrets, no `pull_request_target`, no write tokens.
