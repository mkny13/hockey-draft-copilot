### c. Server origin and Host boundary — Fixed here

- **Fixed here:** When `HOST` is a loopback address (`127.0.0.1`, `localhost`, `::1`, the default),
  `server.js:196-206` enforces a `Host` header check across all HTTP routes via Express middleware,
  and `server.js:387-400,508-514` enforces it in the WebSocket `verifyClient` handshake and connection
  handler. Requests whose `Host` hostname does not match `localhost`, `127.0.0.1`, or `[::1]` (any port),
  or where the `Host` header is missing, receive 403 (or WebSocket handshake rejection). This closes the
  DNS rebinding attack vector against `/draft_data.json` and `/api/state`. If `HOST` is explicitly set to
  a non-loopback address (e.g. `0.0.0.0`), the check is skipped because the operator intentionally
  widened the bind.
- Origin protection: `ALLOWED_ORIGIN` (`server.js:191`) permits only `https://fantasy.espn.com`,
  `https://*.fantasysports.yahoo.com`, and `http(s)://localhost|127.0.0.1` on any port. Non-GET requests
  and `OPTIONS` preflights from foreign origins receive 403; GET requests omit `Access-Control-Allow-Origin`.
- Verified in `test/test_server.js`: foreign `Host` headers return 403 on `/draft_data.json` and
  `/api/state`, foreign `Host` WebSocket handshakes are rejected, loopback variants are accepted, and
  `HOST=0.0.0.0` bypasses the check.

### d. Server input bounds — OK

- Body parsing size limits: `express.json({ limit: '64kb' })` and `express.urlencoded({ limit: '64kb' })`
  in `server.js:174-175`. Over-limit requests return 413; malformed JSON returns 400 (`server.js:178-185`).
- `/api/pick`: player name bounded (1–80 chars, no control characters via `validatePickName`), `round`
  and `pickInRound` bounded via `parseBoundedInt(..., 1, 1000)`, history capped at 2000 entries.
- `/api/repair-pick`: `pickNumber` bounded (1–2000), duplicate player names rejected, cannot target an
  already-occupied pick number, and history capped at 2000 entries.
- `/api/settings`: draft slot and teams bounded; roster limit numbers validated.

### e. Extension — OK

- `yahoo-sync/manifest.json`: permissions restricted to `"storage"`; `host_permissions` and content
  script matches restricted to `https://fantasy.espn.com/*`, `https://*.fantasysports.yahoo.com/*`,
  and `http://localhost:3333/*` (for the background health check).
- `chrome.storage.local` stores only `syncUrl` and `status`.
- `validateSyncUrl` in `background.js:5` and `content.js:8` enforces valid `http:` or `https:` protocols,
  falling back to `http://localhost:3333`. Player names and sync URLs are escaped at render time.

### f. Bookmarklet — OK

- `public/js/bookmarklet.js` sends requests only to `http://localhost:3333/api/pick` and
  `http://localhost:3333/api/reset`. Reset prompts for user confirmation before dispatching. Requests
  carry the draft room's origin, which is permitted by `ALLOWED_ORIGIN` on fantasy draft domains.

### g. MCP server — Fixed here

- **Fixed here:** In `mcp/lib/tools.js:414`, the `schedule` tool validates `team` after normalization
  against `/^[A-Z]{2,3}$/`. If invalid, it throws `team must be a 2-3 letter NHL abbreviation` before
  invoking `S.clubSchedule` or issuing network requests. This prevents path traversal sequences like
  `../x` or invalid path segments from reaching `api-web.nhle.com`.
- Outbound endpoints are restricted to fixed constants in `mcp/lib/sources.js:5-7` (`moneypuck.com`,
  `api.nhle.com`, `api-web.nhle.com`).
- Input arguments (`season`, `playerId`, `date`) are strictly validated prior to fetch.
- Cache filenames use SHA-1 hashes of the request URL; cache writes are best-effort.

### h. Denial lists — Fixed here

- **Fixed here:** `.claude/hooks/block_live_data.py` inspects `tool_input.command` when present to
  protect `draft_state.json` and `draft_data.local.json` from write or deletion actions in `Bash`
  (`>` / `>>` redirects, `tee`, `rm`, `mv`, `cp ... <protected>` destination, `truncate`, `sed -i`).
  Read-only operations (`cat`, `grep`, `jq`) remain permitted. `.claude/settings.json` wires `Bash` into
  the `PreToolUse` matcher.
- `.gitignore` prevents tracking of live runtime state (`draft_state.json`), private boards
  (`draft_data.local.json`), and MCP cache files (`mcp/.cache/`).
